# 一箭又一箭 —— 游戏设计草稿

## 1. 游戏状态机

| 当前状态 | 触发条件 | 转到状态 |
|---|---|---|
| START 开始界面 | 点击"开始游戏" | PLAYING |
| PLAYING 游戏中 | 本关箭头全部消除，且还有下一关 | LEVEL_CLEAR |
| PLAYING 游戏中 | 本关箭头全部消除，且已是最后一关 | ALL_CLEAR |
| PLAYING 游戏中 | 剩余失误变为 0 | GAME_OVER |
| LEVEL_CLEAR 单关通关 | 点击"下一关" | PLAYING |
| GAME_OVER 失败 | 点击"重新开始本关" | PLAYING |
| 各结果界面 | 点击"回到开始" | START |

## 2. 数据结构

- 方向：枚举 `UP / DOWN / LEFT / RIGHT`，对应字符 `U / D / L / R`。
- 网格 grid：二维列表，`.` 表示空格，方向字符表示箭头。
- 关卡 level：字典 `{"mistakes": 失误上限, "grid": 二维网格}`，多关组成 `LEVELS` 列表。
- 棋盘 Board：加载关卡、统计/删除箭头、重置、路径检测（阶段 5）。
- 运行时状态：当前关索引、当前棋盘、剩余箭头数、剩余失误数、动画状态。

## 3. 界面布局

- 顶部信息栏：当前关卡、剩余箭头数、剩余失误次数、"重新开始"按钮。
- 中部：棋盘网格，箭头用多边形绘制。
- 开始界面：标题、规则说明、"开始游戏"按钮。
- 结果界面：单关通关（下一关）、失败（重新开始本关）、全部通关（回到开始）。

## 4. 路径检测规则与伪代码

从被点击箭头的**下一格**开始，沿箭头方向逐格检查：

```text
函数 can_fly(网格, 行, 列):
    方向 = 该格箭头的方向
    (dr, dc) = 方向对应的行列增量
    r, c = 行 + dr, 列 + dc
    当 r、c 仍在棋盘范围内时循环:
        若 grid[r][c] 不是空: 返回 False（被挡住）
        r += dr; c += dc
    走出循环（已出界）都没遇到箭头: 返回 True
```

方向增量：上 (-1,0)、下 (1,0)、左 (0,-1)、右 (0,1)。

## 5. 关卡设计方法：逆向构造法

正向规则：若箭头 B 挡在箭头 A 的飞行路线上，B 必须比 A 先消除。
逆向构造：从空棋盘开始逐个放箭头，每放一个新箭头，只要求**它自己朝向的路线上当前没有已放箭头**（它允许挡在别人的路线上，因为它会先飞走）。
放完后，**按放置顺序的倒序点击，就是一条通关顺序**。

## 6. 三关通关顺序（坐标从 0 开始，格式 (行,列)）

- 第 1 关：(3,0) → (4,4) → (2,2) → (0,0)
- 第 2 关：(2,5) → (4,3) → (5,2) → (3,3) → (1,3) → (0,4) → (0,5)
- 第 3 关：(1,2) → (4,5) → (1,4) → (2,5) → (3,0) → (5,1) → (5,0) → (0,2) → (0,1) → (0,0)
